# LED表示器：シミュレーション用設計 Rev A

入力：添付の倒立した実装写真。出力：信号名ベースの回路図、全端子接続表、動作可能な論理モデル、検証結果、波形。

電気特性の主検証は [LTspice版](ltspice/README.md)。以下のJavaScriptモデルは表示・データ順序の補助確認用。LTspiceで10µs待ちの問題を見つけ、100µsへ修正した。

## 開く・実行する

- `preview.html` をブラウザーで開く。インターネット不要。回路図と表示の走査、強制消灯、2行同時選択の故障注入を確認できる。
- `schematic.svg` は拡大・印刷可能な図面。
- `connections.csv` は同名ネットを接続する端子表。KiCad回路図ファイルやSPICEネットリストではない。
- `scan.vcd` はGTKWave等で開く1フレームの制御波形。1ns単位。行ラッチは内部観測値としてROW_MASKに記録。
- Node.jsで `node simulation/test.cjs`。プロジェクト直下で実行。依存パッケージ不要。
- 図面等を再生成する場合は `node simulation/build.cjs`。

## 写真から読み取れる構成と仮定

|項目|判定|Rev Aでの扱い|

|TLC5928 ×6、74HC595 ×2、ULN2803A ×2、P-MOS行駆動|写真に記載と読み取り|部品機能をメーカー資料と照合。P-MOS型番の読取りは未確定|

## 接続とデータ形式

TLC5928はPW/TSSOP-24のピン配置を採用する。QFNにはこの端子番号を使わない。MOSFETは型番選定前のためG/S/Dの機能端子のみ。`connections.csv`の同じnetが全て同一接続で、NCで始まるネットは未使用出力。

- バッファの電源は5V、/OEはGND。GPIO側のBLANKを10kで3.3Vに、他の入力を10kでGNDに固定する。BLANKの5V側にも10kプルアップを付ける。MCUの電源断時まで含めたバックパワー耐性は別途確認する。
- 赤3個のTLCと行595はSCLK_R/LAT_Rを共用。緑3個はSCLK_G/LAT_Gを共用。
- 各TLC OUT0..15をその表示器の赤または緑の16カソードへ接続する。
- 74HC595の行Q=1 → ULNの出力がLow → P-MOSゲートがLow → その行アノードに5V供給。
- ULN2803Aはゲートの駆動専用。LEDの行電流を供給する素子ではない。
- 外部5Vと全GNDを接続する。MCUはUSB給電。外部5VをUSBのVBUSに直結する設計にはしていない。

フレームは `frame[y][x]`、y=0..15、x=0..47。色コードは0=消灯、1=赤、2=緑、3=両色。x=0..15がLED1、16..31がLED2、32..47がLED3。上下左右の実物との対応は未確認。

赤の転送は64bit、MSB先行。送信順は行15→行0、LED3の赤OUT15→0、LED2の赤OUT15→0、LED1の赤OUT15→0。緑は48bit、LED3→LED2→LED1の各OUT15→0。

## 起動・行切替の手順

起動時はBLANK_R/GをHに保ち、赤64bit・緑48bitのゼロを書き込み、各LATを1回だけ上げる。行が全消灯となる。ラッチが電源投入でゼロになるとは仮定しない。

各1msの行スロットで以下を実行する。

|区間|時間|動作|
|---|---:|---|
|切替開始|1µs|両BLANK=H、出力OFF待ち|
|赤転送|64µs|1MHzで行16bitと赤48bitを送信|
|緑転送|48µs|1MHzで緑48bitを送信|
|ラッチ前ガード|1µs|SCLKをLで保持|
|ラッチ|1µs|両LATをHにしてLへ戻す|
|行安定待ち|100µs|両BLANK=Hを維持|
|表示|785µs|両BLANK=L|

TLC5928のLAT上昇でシフトレジスタは診断データに置き換わる。更新データを再送せずLATを2回上げてはいけない。次のSCLK上昇はLAT上昇後100ns以上空ける。ここではµs単位のガードを採用する。実デバイスのセットアップ・ホールド・配線遅延を合否判定したものではない。

100µsの行安定待ちは暫定値。ULNの解放、ゲートの10kプルアップ、選ぶMOSFETのゲート電荷で消灯側遅延が変わるため、実機のゲート/アノード波形で調整する。

## 電源・明るさの一次計算

データシート式は I=1.20V×42/R_IREF。3.3kΩで約15.27mA。16行走査、各785µs点灯では1LEDの実効Duty=4.91%、平均電流は約0.749mA。明るさは実物で確認する必要がある。

赤緑両方・48列点灯時に96経路がONとなり、1行のLED電源ピークは約1.47A、LED分だけの平均は約1.15A。ロジック・MCU・損失・余裕は含まない。電源定格やヒューズは未選定。

各TLCの全16出力が毎行ONの場合、ドライバ損失の概算は `16 × 15.27mA × (5V − V_PMOS − Vf_LED) × 0.785` に内部消費を加える。例えば仮にVf=2V、PMOS降下を無視すると出力段だけで約0.58W/ICになる。1/16を掛けない。同じTLCが全行で動き続けるため。パッケージ・基板放熱・周囲温度による熱設計が必要で、本シミュレーションでは検証していない。

## 検証範囲・合格条件

実行結果は `test-results.json`。9項目がPASS。

|検証|合格条件|
|---|---|
|不定ラッチでの起動|BLANK=H中に点灯しない|
|全1,536色経路の個別点灯|対象座標・対象色だけがON、行選択がone-hot|
|7パターンの全フレーム|16行を再構成した画像が入力と一致|
|シフト中の保持|LAT前は出力画像が変わらない|
|色別BLANK|赤/緑が独立して消灯できる|
|LAT二重パルス注入|診断データへの置換で表示が変わる|
|複数行の故障注入|2本の選択と別行の点灯を観測できる|
|ビット順逆転の故障注入|入力画像と不一致になる|
|不正入力|行範囲外、色コード範囲外を拒否|

故障注入のPASSは「故障が再現・観測できた」という意味。回路自体が故障を検知・遮断する機構は実装していない。

理想化するもの：バッファ、立上りエッジ、ULNとP-MOSの極性、LEDのON/OFF。診断シフトデータは0固定。再現しないもの：MCU命令・USB通信、SPICE電気特性、定電流制御のコンプライアンス、LED Vf、複数行時の電流分配、寄生容量、電源ディップ、発熱、EMI、実時間保証。
